# Self-Heal Coding Agent Setup

This repository has been configured with an adaptive, self-healing CI automation pipeline designed to automatically fix code drift, regenerate snapshots, update dependencies, and run formatting/linting auto-fixes.

## System Architecture

The pipeline consists of the following components:

1. **`scripts/healthcheck.mjs`**: An all-in-one script that verifies the repository is healthy (lint, build, types, tests). It fails fast if any of these are broken.
2. **`scripts/self_heal.mjs`**: The core repair loop. It executes six idempotent steps in order:
    - Rebuild/reinstall (npm ci)
    - Lint/format auto-fix (eslint/prettier)
    - Update test snapshots (vitest run -u)
    - Update type stubs (typesync)
    - Dependency re-resolve (npm update)
    - Static asset regeneration (build)
   After every step, it re-runs the healthcheck. If the healthcheck passes AND a diff was generated, it succeeds.
3. **`scripts/compute_schedule.mjs`**: Adaptive scheduling logic. It analyzes `git log` metrics over the past 7 days to dynamically tune the cron trigger, preventing thrash while staying responsive to high-velocity development periods.
4. **`.github/workflows/self-heal.yml`**: The GitHub Actions workflow that orchestrates the above scripts. It contains strict gates, secret scanning, loop prevention, and duplicate PR handling.
5. **`.github/workflows/compute-schedule.yml`**: Periodically (weekly) recalculates the telemetry and auto-PRs a new cadence if necessary.
6. **`.github/self-heal-schedule.yml`**: State management for the scheduling logic, containing the current cron string, the rationale, and an oscillation guard (`last_updated`).

## Triggers

The Self-Heal workflow runs in three modes:
- **Proactive (Scheduled)**: Runs on a self-computed cadence (e.g., every 4 hours during active bursts, weekly during dormancy).
- **Reactive (CI Failure)**: Runs immediately when the `PR Review` workflow fails on a Pull Request.
- **Manual (Dispatch)**: Can be triggered via the GitHub Actions UI anytime.

## Reviewer Checklist

When reviewing a PR generated by the `selfheal-*` automation:
- [ ] Verify no actual business logic was maliciously or inadvertently altered.
- [ ] Verify the drift was strictly isolated to tooling (e.g. snapshots, types, `package-lock.json`, or `.prettierrc`).
- [ ] Ensure no secrets were committed (the agent is designed to block this, but human review is mandatory).

## Overrides

To manually override the self-healing schedule, edit `.github/self-heal-schedule.yml` and set the `last_updated` date forward into the future to force the oscillation guard to respect your manual `schedule` string.
