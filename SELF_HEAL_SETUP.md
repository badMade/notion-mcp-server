# Self-Heal Coding Agent Setup

This repository has a self-healing pipeline that automatically attempts to fix CI failures and code drift.

## Triggers
- **Scheduled**: Runs periodically to detect and fix code drift. The schedule is computed dynamically based on repository telemetry (PR velocity, CI failures).
- **Reactive**: Runs immediately after a `ci` workflow failure.
- **Manual**: Can be triggered manually via workflow dispatch.

## Repair Pipeline
The repair script (`scripts/self_heal.mjs`) attempts the following steps idempotently:
1. Rebuild/reinstall (npm ci)
2. Lint/format auto-fix (eslint, prettier)
3. Snapshot/generated updates (vitest -u)
4. Type stubs/analyzer config (typesync)
5. Dependency re-resolve (npm install --legacy-peer-deps)
6. Static asset regeneration (npm run build)

After each step, a healthcheck (`scripts/healthcheck.mjs`) is run. If the healthcheck passes and there are code changes, a PR is opened.

## Self-Scheduling
The schedule is evaluated periodically by `scripts/compute_schedule.mjs`. It reads telemetry (PR velocity, CI failure rate) and adjusts the schedule tier (high, active, standard, low, dormant).
The current schedule and rationale are stored in `.github/self-heal-schedule.yml`.

## Customization and Overrides
To manually override the schedule, edit `.github/self-heal-schedule.yml` and ensure the `# AUTO-UPDATED` marker is present. The `compute_schedule` script will respect changes but recompute if telemetry indicates a significant shift.

## Reviewer Checklist
- Review the diff generated by the self-healing agent.
- Ensure no unintended logical changes were introduced.
- Merge the PR once CI passes on the self-heal branch.
